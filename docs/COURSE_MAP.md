# Карта учебного репозитория TIP-JS

Источник: [adyshkins/TIP-JS](https://github.com/adyshkins/TIP-JS), изученная редакция `37fd64e6f09e728e60e6304d50eda07c398bbd1c`, 04.10.2026.

## Состав и общий замысел

В репозитории опубликованы 14 практических работ и лекция № 2 с браузерным примером. В корневом README дан план семи лекций. Остальные лекционные файлы в изученной редакции отсутствуют.

Курс развивает одно приложение управления задачами. В начале это расчётные скрипты, затем модель задач и интерфейс. Позже добавляются HTTP, React, собственный API, PostgreSQL, тесты и подготовка релиза.

| Работа | Основная задача | Что сохраняется для следующего этапа |
|---|---|---|
| ПР1 | Node.js и браузер; типы, условия, циклы, отладка | Окружение и личный Git-репозиторий |
| ПР2 | Девять функций работы с задачами; `find`, `filter`, `map`, копирование | Независимый модуль логики и индивидуальный набор |
| ПР3 | DOM, делегирование событий, фильтры, сводка | Работающий браузерный интерфейс |
| ПР4 | Форма создания и редактирования, валидация, JSON, localStorage | Приложение с локальным сохранением |
| ПР5 | Promise, async/await, JSON-клиент, отмена и тайм-аут | HTTP-клиент и предметный API |
| ПР6 | Браузерный клиент готового API; GET, POST, PATCH, DELETE | Интерфейс с серверными данными |
| ПР7 | Компоненты React и состояние в памяти | React-версия интерфейса |
| ПР8 | React и API; эффекты, отмена, защита от устаревших ответов | React-клиент для своего сервера |
| ПР9 | Собственный Express API чтения, фильтры, валидация query | Серверные маршруты и контракт |
| ПР10 | Операции записи и подключение React-клиента ПР8 | Собственное приложение с CRUD в памяти |

До ПР12 данные собственного API находятся в памяти процесса. В ПР3 изменения сбрасываются при обновлении страницы; в ПР4 сохраняются в localStorage. Эти этапы нельзя смешивать в отчёте.

## Как выполнять и сдавать

1. Сохранять решения в своём репозитории, отдельно от методичек преподавателя.
2. Для ПР1 самостоятельно создать файлы по инструкции. Для ПР2–ПР14 переносить вложенную папку `practice-XX` из `starter` в корень личного репозитория.
3. Сохранять предыдущие работы. Папки `practices` и `starter` в свой репозиторий переносить не нужно.
4. Заполнять `practice-XX/README.md`: автор, группа, вариант, команды запуска, реальные результаты и объяснение ошибок. Для первых трёх работ отдельный Word/PDF не требуется.
5. Выполнять общий сценарий и свой вариант. Готовые проверки преподавателя сохранять без удаления неудобных случаев.
6. Отправлять код, отчёт и результаты на GitHub; преподавателю передавать ссылку на папку работы.
7. На защите уметь запустить программу, объяснить решение и внести небольшое изменение.

Успешные автоматические проверки сами по себе не заменяют отчёт, вариант и защиту. Сроки сдачи и официальная балльная система в корневом README не устанавливаются.

## Вариант и ограничения первых работ

В этих решениях ПР1–ПР3 используется вариант 7. В ПР1 обязательные решения не используют собственные функции и массивы; ПР2 вводит эти средства. В ПР3 сервис не зависит от DOM, а отображение использует `textContent` для названий.

В ПР14 опубликовано другое правило при отсутствии отдельного назначения: остаток номера в списке при делении на 14, остаток 0 означает 14. При переходе к ПР14 нужно сверить назначение преподавателя; автоматически переносить вариант 7 на эту работу нельзя.

## Происхождение файлов

`practice-02/checks.js`, примеры ПР2, `practice-03/checks/*`, `checks.html`, HTML/CSS, примеры DOM и локальный сервер взяты из стартовых комплектов преподавателя. Проверочные файлы оставлены без изменений. Заглушки прикладных модулей заменены решениями. Данные варианта и отчёты заполнены отдельно.
