## Как показать работу

1. В ПР1 запустить `progress.js` и `plan.js`: осталось 3 задачи, прогресс 70.0%, нужен один день. Затем показать общий пример 12 / 5 / 3: три дня, в последний день одна задача.
2. В ПР2 запустить `node practice-02/src/main.js`, затем стандартные и собственные проверки. Объяснить одну операцию обновления.
3. В ПР3 запустить сервер, открыть общий набор и свой вариант. Показать фильтр, изменение статуса по вложенному тексту кнопки, удаление и два пустых состояния.

## ПР1: каждый файл

| Файл | Что делает | Что объяснить |
|---|---|---|
| `hello.js` | Выводит автора, группу и тип `document` | Один язык работает в разных средах: в браузере есть DOM, в Node.js его нет |
| `types.js` | Проверяет десять выражений | `+` со строкой соединяет текст; `-` приводит операнды к числам; `typeof` возвращает строку |
| `progress.js` | Проверяет количества и считает сводку | Сначала ошибки, затем пустой список, затем деление и статус |
| `plan.js` | Распределяет оставшиеся задачи циклом `while` | На каждом шаге остаток уменьшается; `Math.min` ограничивает последний день |
| `debug.js` | Исправляет сложение строк и границу цикла | `Number` нужен до сложения, `<= 4` включает четвёртое число |
| `debug-original.js` | Сохраняет исходные ошибки | Это материал для сравнения, а обязательное исправленное решение — `debug.js` |

В `progress.js` `Number.isInteger` одновременно отклоняет строки, дроби, `NaN` и бесконечность. Далее проверяются границы 0–1000 и условие выполнено ≤ всего. Для пустого списка процент не вычисляется.

Формула процента: `completedTasks / totalTasks * 100`. `toFixed(1)` применяется только при выводе. Статус выбирается по исходным количествам, поэтому округление не влияет на решение.

В `plan.js` переменные `remainingTasks` и `day` меняются, поэтому объявлены через `let`. Входные данные и дневное количество объявлены через `const`. Сначала проверяется лимит даже при нулевом остатке.

Пример 12 / 5 / 3: остаток 7 → 4 → 1 → 0; дневные количества 3, 3, 1. Пример своего варианта 10 / 7 / 3: остаток 3 → 0, один день.

### Краткие ответы на контрольные вопросы ПР1

1. JavaScript — язык, Node.js — среда выполнения. `document` предоставляет браузер.
2. `const` запрещает новое присваивание переменной, `let` разрешает. Для объекта `const` не запрещает изменение его полей.
3. `12` — число, `"12"` — строка; их типы различаются.
4. Если при сложении один операнд строка, возможно соединение текста: `"8" + 2` даёт `"82"`.
5. `===` сравнивает без преобразования типов; `12 === "12"` — `false`.
6. `Number("")` даёт 0, хотя пустой ввод может быть ошибкой. Сначала проверяют саму строку.
7. Тип `number` есть и у дроби, `NaN`, `Infinity`. Нужны целочисленность и ограничения.
8. Ошибки → пустой список → обычный расчёт. Это предотвращает деление на ноль.
9. Остаток уменьшается на положительное число. При нулевом лимите цикл мог бы не закончиться.
10. В конце может остаться меньше лимита. `Math.min` выбирает реальный остаток.
11. Точка останова позволяет увидеть значения и выполнить отдельный шаг до получения итогового вывода.
12. Сохранение меняет файл; коммит фиксирует версию локально; push передаёт коммиты в удалённый репозиторий.

## ПР2: модель, функции и ссылки

Задача имеет четыре поля: положительный безопасный целочисленный `id`, строковое название длиной 1–100 после `trim`, логический `completed`, приоритет `low` / `medium` / `high`.

`data.js` содержит исходные наборы. `task-service.js` реализует логику без вывода и DOM. `main.js` запускает последовательность действий и показывает результаты.

| Функция | Как работает | Результат |
|---|---|---|
| `createTask` | Проверяет аргументы, удаляет краевые пробелы, задаёт `completed: false` | `{ ok: true, task }` или `{ ok: false, error }` |
| `findTaskById` | `find` со строгим сравнением `task.id === id` | Исходный объект или `undefined` |
| `getPendingTasks` | `filter` по `completed === false` | Новый массив невыполненных задач |
| `getTaskTitles` | `map` берёт название каждой записи | Новый массив строк |
| `getTaskStats` | Считает длину, выполненные, остаток и процент | Объект с четырьмя числами |
| `addTask` | Вызывает создание, проверяет дубликат, использует spread массива | Новый массив с задачей в конце |
| `setTaskCompleted` | Проверяет boolean, обновляет одну запись через `map` и spread объекта | Новый массив и новый объект выбранной задачи |
| `renameTask` | Проверяет название, обновляет только `title` | Новый массив и новый объект выбранной задачи |
| `removeTask` | Проверяет наличие и отбирает записи с другим `id` | Новый массив без задачи |

Внутренние `isValidId` и `isValidTitle` нужны, чтобы не повторять условия в нескольких функциях. Они возвращают `true` или `false`.

При изменении записи выражение `{ ...task, completed }` копирует её поля, а затем заменяет статус. Остальные объекты можно использовать повторно: их свойства не изменяются. Spread массива копирует только массив, а не автоматически все объекты внутри него.

Успешная операция возвращает новый массив. В сценарии он становится `currentTasks` только после `result.ok`. Ошибка дубликата не меняет состояние. `JSON.stringify` используется в демонстрации и проверках для сравнения небольших объектов этой модели.

Для общего сценария итог — id `[1, 4, 10, 20]`, 4 задачи, 3 выполнены, 75.0%. Для варианта 7 итог — `[11, 23, 41, 58, 64, 80]`, 6 задач, 5 выполнены, 83.3%. Новая задача 80 не выполнена; удаляемая задача 37 была выполнена.

### Краткие ответы на контрольные вопросы ПР2

1. Параметр — имя во время объявления функции, аргумент — значение при вызове. `return` передаёт результат вызывающему коду, `console.log` выводит его.
2. У стрелочной функции с `{}` нужен явный `return`; иначе результат `undefined`.
3. Значение по умолчанию используется при пропуске аргумента или `undefined`, но не при `null`.
4. `const` запрещает заменить ссылку другим значением, а не изменить свойства объекта.
5. `===` у объектов сравнивает ссылки. Два отдельных объекта могут иметь одинаковые поля и разные ссылки.
6. `[...tasks]` создаёт новый массив с прежними ссылками на записи. Для копии записи используют `{...task}`.
7. `find` возвращает одну запись; `filter` — массив подходящих; `map` — массив результатов преобразования. Изменение исходного объекта внутри callback всё равно является мутацией.
8. `id` обозначает запись, индекс — её положение. У задачи id 4 индекс может быть 1.
9. Уникальность проверяет `addTask`: только у него есть список. `createTask` списка не получает.
10. `"false"` — непустая строка, а не boolean. Неявное преобразование дало бы `true`.
11. Создаются новый массив и новый объект изменяемой записи. Неизменённые объекты можно сохранить.
12. Новый массив может содержать уже испорченный исходный объект. Нужно сравнить и поля, и ссылки.
13. Число пригодно для дальнейших расчётов; форматирование строки относится к отображению.
14. Ожидаемый отказ возвращается через `ok: false`. Программная ошибка, например неверный импорт, требует исправления кода.
15. `type: module` включает ES-модули. `export` предоставляет функцию, `import` подключает её. Сервис получает массив аргументом и не зависит от конкретных данных.
16. Сервис сохраняется. Браузерный модуль обрабатывает события, вызывает сервис и отображает результат.

## ПР3: путь от нажатия к новой карточке

`currentTasks` — весь текущий список. `currentFilter` — выбранный режим. `getVisibleTasks` вычисляет отдельную выборку для отображения.

| Функция | Назначение |
|---|---|
| `getVisibleTasks` | Возвращает новый массив всех, выполненных или невыполненных задач |
| `createTaskElement` | Создаёт одну `li` с названием, статусом, приоритетом и двумя кнопками |
| `renderTaskList` | Заменяет дочерние карточки, сохраняя сам `ul` |
| `renderSummary` | Считает сводку полного списка; отдельно выводит длину выборки |
| `renderEmptyState` | Различает пустой список и отсутствие совпадений фильтра |
| `renderApp` | Вычисляет выборку и согласованно обновляет интерфейс |
| `handleTaskListClick` | Находит кнопку и карточку, проверяет id, вызывает сервис и обновляет состояние |
| `handleFilterClick` | Проверяет режим, меняет только фильтр и обновляет интерфейс |
| `restoreTaskFocus` | Возвращает фокус на новую кнопку либо активный фильтр |

При клике по `span.action-label` непосредственная цель — `span`. `closest("button[data-action]")` находит родительскую кнопку. Затем обработчик читает `data-task-id` карточки. В `dataset` находится строка: нужен `Number` и проверка безопасного целого.

Текущий статус берётся из массива через `findTaskById`, а не из класса карточки. Сервис получает `!task.completed`. При успехе `currentTasks = result.tasks`, после чего вызываются отрисовка и восстановление фокуса.

Обработчики назначаются один раз постоянным контейнерам. В `renderApp` подписок нет, поэтому повторные фильтры не умножают число обработчиков. `replaceChildren` сохраняет контейнер списка, но заменяет его карточки.

Название выводится через `textContent`. Строка `<strong>Проверка</strong>` остаётся текстом. Сводка берётся по полному списку, даже если видна только одна задача.

Вариант 7 начинается с 6 / 6 / 0 / 100.0%. Переключение задачи 23 снимает выполнение: 6 / 5 / 1 / 83.3%. Удаление выполненной 37 даёт 5 / 4 / 1 / 80.0%.

### Краткие ответы на контрольные вопросы ПР3

1. HTML — исходная разметка. DOM — текущие объекты документа, которые JavaScript может менять.
2. `querySelector` возвращает `null`, `querySelectorAll` — пустой `NodeList`.
3. `querySelectorAll` возвращает статическую коллекцию: для нового состояния нужен новый запрос.
4. `createElement` создаёт узел отдельно. `append` помещает его в документ.
5. `textContent` показывает название как текст и не выполняет HTML-разметку.
6. `target` — нажатый `span`, `currentTarget` — контейнер с выполняемым обработчиком.
7. Всплытие доставляет событие контейнеру; `closest` находит кнопку; `contains` проверяет её принадлежность.
8. `dataset` хранит строку, сервис ожидает числовой id. Статус в массиве — источник данных.
9. id не равен индексу. `parseInt("4abc")` дал бы 4, поэтому используется `Number`, получающий `NaN`.
10. Подписка в каждом рендере могла бы создавать несколько обработчиков одного события.
11. Меняется фильтр; полный список сохраняется. Меняется только видимая выборка.
12. Удаление узла не меняет массив, поэтому следующий рендер вернул бы задачу.
13. Нужны новый массив, выборка, список, общая сводка, «Показано», пустое сообщение и фокус.
14. При пустом списке `total = 0`; при отсутствии совпадений `total > 0`, но `visibleCount = 0`.
15. При отказе нет `result.tasks`; без проверки состояния можно присвоить `undefined` и сломать рендер.
16. Чистый сервис тестируется в Node.js и пригоден для другого интерфейса, включая React.
17. Проверяют Tab, Enter и Space и смотрят, куда попадает фокус после замены карточки.
18. Node.js проверяет сервис. Браузер проверяет DOM и действия. Отдельно проверяют вариант, клавиатуру, внешний вид и понимание кода.
